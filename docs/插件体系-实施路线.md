# 疏音 · 插件体系实施路线

> 依据：2026-11-09 四轮讨论（插件面盘点 → 可行性分级 → 宿主 API 面 → 边界拍板）
> 用途：供后续 AI 按阶段逐步实现。每个阶段**独立可交付、可验证、可停在任意一格**。
> 结论先行：**这个项目已经是半插件架构，不需要造通用插件运行时**。已有 LX 音源脚本（Worker 沙箱 + 受控出网 + 降级链）与 `PlatformApi` 契约（12 方法）两样资产，缺的只是「清单 + 能力网关 + 三个宿主接口」。

---

## 0. 三条硬边界（不可协商，所有阶段都受它约束）

1. **插件只能是运行时加载的 JS，不能自带原生代码。**
   安卓是换壳（前端产物打包进 `assets/www`，随 APK 分发），一旦允许原生插件，构建链路、ABI、签名全要重做，桌面和安卓立刻分裂成两个生态。插件的能力**全部由宿主给**。
2. **插件永远拿不到 `invoke()`。**
   `bridge.ts` 是三宿主统一入口（Tauri `invoke` / 安卓 `androidInvoke` / 浏览器 mock）。插件绕过它就等于安卓端必崩。所有能力必须先在网关里开一个**带权限的名字**。
3. **两端行为必须一致。**
   同一个插件在桌面与安卓上必须能跑出同样结果。做不到一致的能力（音频后处理、本地 HTTP server、窗口控制）**不开放**，而不是"只给桌面"。

## 1. 现状：已经是半插件

| 资产 | 位置 | 已具备 | 缺什么 |
|---|---|---|---|
| 音源脚本运行时 | `lib/lxWorkerBoot.ts`（103 行）、`lxWorkerHost.ts`（207 行）、`packages/lx-provider/src/sourceManager.ts`（561 行） | Worker 隔离执行、目录扫描、`inited` 握手、6s 单源超时、降级链、启停、错误回传、`outbound` 域名声明、`lx.request` 统一出网 | 没有 manifest、没有版本、没有权限、没有插件目录约定 |
| 平台 API 契约 | `packages/lx-provider/src/types.ts` 的 `PlatformApi` | 12 个方法 + `supports*` 能力位 + 全可选方法，质量足够当公开契约 | `PlatformSource` 是字面量联合（`'kw'\|'kg'\|'tx'\|'wy'\|'mg'`），第三方进不来；`platforms/index.ts` 的 `FACTORIES` 是编译期常量 |
| 主题引擎 | `packages/theme-engine/src/index.ts`（584 行） | `ThemeTokens`（30 字段）+ `ThemeDef` + 校验 + 导入导出，**主题本来就是数据不是代码** | token 全是颜色与少量数值，只能"改色"，没有字体/滤镜/动效曲线 |
| 数据层 | `onlineId = online:${source}:${id}`、`platPrefs` 键 `${source}:${id}` | 全是字符串拼接，插件天然兼容 | — |

**结论**：插件面不缺运行时，缺三样——契约公开、清单与生命周期、能力网关。

## 2. 阶段总表（按难易排序）

难度：L1 最易 → L5 最难。工作量按现有代码密度估算。

| 阶段 | 内容 | 难度 | 工作量 | 依赖 | 交付后立刻能写什么 |
|---|---|---|---|---|---|
| **S0** | 最小插件运行时（清单 + 目录 + RPC + `log`/`toast`/`storage`/`net`） | L2 | 2–3 天 | 无 | scrobble、Webhook、纯网络类插件 |
| **S1** | 事件层 + `library.query` | L2 | 2 天 | S0 | 自动规则、智能歌单、听歌统计 |
| **S2** | 播放控制 + 借宿主平台层 | L2 | 1 天 | S1 | 相似歌曲、跨平台找同名、推荐 |
| **S3** | 可视化插件插槽（canvas） | L2 | 3 天 | S0 | 频谱/可视化插件（出圈品类） |
| **S4** | 主题升格为"视觉语言" | L1 | 2 天 | 无 | 主题包（含字体/滤镜/动效） |
| **S5** | 平台插件地基（`PlatformSource` 去字面量）+ Subsonic 官方示例 | L4 | 1.5–2 周 | S2 | 接自建库（NAS 用户） |
| **S6** | 歌词源管道（`getLyric` 从平台层剥离） | L3 | 3–5 天 | S1 | 多源歌词、逐字歌词 |
| **S7** | 声明式 UI slot | L5 | 2 周+ | S3 | 播放页小组件、详情扩展卡 |

**节奏建议**：S0→S1→S2→S3 连做约两周，就能凑出「市场首批 5–8 个插件」的弹药，且全是低风险项。**S7 建议本版完全不做**，维护成本（组件白名单、主题兼容、布局回归、两端一致）远超收益，而 S3 已经能满足"视觉扩展"。

**进度勾选**（每完成一个阶段就打勾并写日期，后续 AI 从这里接着做）

- [ ] **S0** 最小插件运行时（清单 / 目录 / RPC / `log`·`toast`·`storage`·`net`）
- [ ] **S1** 事件层（`track`·`state`·`queue`·`progress`·`lyric`）+ `library.query`
- [ ] **S2** 播放控制 + 借宿主平台层（免登录 5 个）
- [ ] **S3** 可视化插件插槽（canvas）
- [ ] **S4** 主题升格为视觉语言（新 token 字段）
- [ ] **S5** 平台插件地基（`PlatformSource` 去字面量）+ Subsonic 官方示例
- [ ] **S6** 歌词源管道（`getLyric` 剥离）
- [ ] **S7** 声明式 UI slot（**默认不做**，需明确批准）

> 开工前先读第 0 节的三条硬边界与附录 D 的实现约束；每个阶段结束跑 `tsc --noEmit` + `vite build`，不主动编译出包。

## 3. 各阶段施工说明

### S0 · 最小插件运行时（L2，2–3 天）

**目标**：放一个目录进 `plugins/`，宿主能解析清单、装载、启停、暴露 4 个零风险能力、能看日志。

**前置**：无。

**改动点**

1. 新建 `apps/desktop/src/lib/plugin/` 目录：
   - `manifest.ts` — 解析 + 校验 `plugin.json`（id 命名规则 `^[a-z0-9][a-z0-9-]{1,31}$`、`engine` semver 检查、未知能力名报错不静默）
   - `host.ts` — 装载器：扫描目录 → 解析 → 起 Worker → 握手 → 状态机（`loading/ready/error/disabled`）
   - `bridgeApi.ts` — 能力网关，RPC 分发
   - `events.ts` — 事件总线（S1 填充）
2. Worker 启动脚本**复用 `lxWorkerBoot.ts` 的模式**（字符串生成、不 import 任何运行时依赖），新增 `pluginWorkerBoot.ts`。为什么不复用同一个文件：LX 脚本的 `lx` 全局是洛雪规范，插件的 `host` 是要长期冻结的自有规范，混在一起以后拆不开。
3. 目录约定（两端各一处，语义对齐）：
   - 桌面：`%APPDATA%\cn.shuyin.player\plugins\<id>\`
   - 安卓：`files/plugins/<id>/`（`Sy.files` 下，与 `sources/` 同级）
4. 原生侧**新增一个命令**：`plugins_default_dir`（桌面 `lib.rs`、安卓 `Bridge.kt`），与现有 `sources_default_dir` 同形状。**不要**复用 `sources_default_dir`。
5. 设置页新增「插件」面板（可先在现有「音源」分类里加一段，不新开分类）：列表、启停、打开目录、日志。

**v1 开放的能力（仅这 4 个）**

```ts
host.call('log',     { level, msg })
host.call('toast',   { text, kind: 'info'|'ok'|'bad' })
host.call('storage', { op: 'get'|'set'|'remove'|'keys', key, value })
host.call('net.request', { url, method?, headers?, body?, timeout? })
```

- `storage`：键自动加前缀 `plugin:<id>:`，**落独立的 `plugins-storage.json`，不写进 settings store**。配额默认 256KB，超限抛错不回退。理由：`settings` 里是宿主配置（`queueTracks`、`localPlaylists`……），插件写坏一次就清空用户队列。
- `net.request`：域名白名单来自 manifest `permissions.net`，越界直接拒绝并报可读原因（"本插件未声明访问 xxx.com"）。底层直接调 `bridge.invoke('net_request', …)`，桌面走 `net::request`、安卓走 `Http.kt`——**沿用 LX 音源已验证的那条路**。
- 请求频率上限：单插件 30 次/分钟，超出退避。没有这条，一个写错的插件能把四个平台的接口打到限流。

**验收**

- 放一个 hello 插件进目录 → 设置页出现、可启停、`log` 能在面板看到。
- 故意写坏 `manifest.json`（缺 id / engine 不匹配 / 未知能力名）→ 面板显示具体错误，不崩、不静默。
- 插件里请求一个未声明域名 → 拒绝且报错文案可读。
- 插件写 300KB 到 storage → 抛配额错误，宿主配置无变化。
- `tsc --noEmit` + `vite build` 通过。

**坑（务必看）**

- 合成消息不能用 `JSON.stringify` 直接塞函数；`postMessage` 只能传结构化克隆安全的值。`raw` 之类不可克隆对象**不要**进 RPC。
- Worker 里 `console` 必须像 `lxWorkerBoot.ts` 那样重定向到 `post({type:'log'})`，否则插件的日志用户永远看不到。
- 插件超时与崩溃：`onerror` + `onmessageerror` 都要接，状态切 `error` 并把原因显示出来。**不要**自动重启（会变成崩溃循环）。

**本阶段不做**：事件、播放控制、曲库、平台层、UI、可视化、主题。

### S1 · 事件层 + `library.query`（L2，2 天）

**目标**：给插件语义化事件与可分页的曲库查询。**这两个接口宿主自己也能用**，不算为插件白做。

**前置**：S0。

**为什么必须先补（现状缺陷）**

- 现在唯一的播放事件通道是 `player://state`，**250ms 一帧（4Hz）且无差别广播**。直接透给插件，十个插件就是 40 次/秒跨线程消息。这个项目为了 120Hz 满帧连队列抽屉的大半径阴影都摘了，这个口子不能开。
- 曲库只有 `get_all_tracks`（`src-tauri/src/db.rs:673`，SQL 是一条 `ORDER BY title` 全表）。没有 filter / limit / offset。上万首时"智能歌单"插件只能把整库序列化进 Worker——几 MB JSON，必卡。

**改动点**

1. `src-tauri/src/db.rs` 新增 `query_tracks(&Db, &TrackQuery) -> Result<(Vec<LocalTrack>, i64)>`：
   ```rust
   pub struct TrackQuery {
     pub text: Option<String>,        // 标题/歌手/专辑 LIKE
     pub artist: Option<String>,
     pub album: Option<String>,
     pub format: Option<String>,
     pub min_duration: Option<f64>,
     pub max_duration: Option<f64>,
     pub added_after: Option<i64>,
     pub sort: Option<String>,        // title|artist|added|duration
     pub limit: i64,                  // 上限 200，服务端强制夹
     pub offset: i64,
   }
   ```
   新建命令 `query_tracks`，**保留 `get_tracks` 不动**（现有 UI 依赖它，改了会牵连全局）。
2. 安卓 `Bridge.kt` 新增 `query_tracks`：`Library.tracks()` 本来就是内存里的全量列表，直接在 Kotlin 侧过滤 + 分页即可，**不要**为了对齐去读数据库。
3. `PlayerProvider.tsx` 增加事件派发（不是新增 state）：
   - `track` — 由 `currentTrack(queueState)` 变化触发，payload 含 `{ id, title, artist, album, source, duration, isOnline, isFirstPlay }`
   - `state` — 由 `snapshot.playing` 翻转触发（**不要**按 position 触发）
   - `queue` — `queueState` 引用变化时触发
   - `progress` — **必须插件显式订阅**，且带 500ms 节流
   - `lyric` — `lyrics` 变化时触发
4. `plugin/events.ts` 里做订阅聚合：同一事件在插件侧注册多份只走一次序列化。

**验收**

- 插件 `on('track')` 在换歌时恰好触发一次（连点下一首不会漏、不会重复）。
- 插件不订阅 `progress` 时，一帧都收不到（用计时器数消息数验证）。
- `query_tracks` 分页正确：`limit=200` 请求 1000 条只回 200，`total` 是真实总数。
- 桌面与安卓返回的 `total` 一致（同一曲库前提下）。
- 现有搜索页 / 曲库页行为无变化。

**坑**

- `track` 事件不能在 render 里发（会与 React 提交顺序打架）。放在已有的 effect 里，按 id 比较，**按 `id` 不按对象引用**（`trackOfId` 每次都造新对象）。
- `progress` 的 500ms 节流要用「最后一次时间戳 + 补发」，不要用 `debounce`（会把中间过程全丢掉，插件画进度条会一顿一顿）。

### S2 · 播放控制 + 借宿主平台层（L2，1 天）

**目标**：插件能控制播放、能白嫖宿主的四平台搜索。这是**别家给不了的差异化**。

**前置**：S1。

**改动点**

1. 网关新增播放控制（复用 `PlayerCtx` 已有方法，不新增底层命令）：
   ```ts
   host.call('player.control', { op: 'play'|'pause'|'toggle'|'next'|'prev'|'seek'|'volume'|'mode', value? })
   host.call('player.enqueue', { trackIds, mode: 'now'|'next'|'end' })
   ```
2. 防抢控制权：控制类调用带 `origin: 'plugin:<id>'` 透传给 `PlayerProvider`，在 UI 上（播放条）不额外显示来源，但**限频 10 次/秒**，超限丢弃并记日志。理由：一个自动规则插件写错循环就能把 `next` 刷成死循环。
3. 平台层代理（**只开免登录接口**）：
   ```ts
   host.call('platform.search',    { source, keyword, page, limit })
   host.call('platform.getPlaylistDetail', { source, id, page?, limit? })
   host.call('platform.getLyric',  { source, songmid, id? })
   host.call('platform.getPic',    { source, song })
   host.call('platform.getComments', { source, song, page?, limit? })
   ```
   实现直接转给 `online.ts` 里已有的 `createPlatformApi` 实例，**不要**另起一套。
4. **绝对不开放的账号接口**：`getUserPlaylists`、`getDailyRecommend`、`getForYouPlaylists`、`getAccount`、`logout`、`HttpClient.cookieFor`。这些会读到用户账号数据。

**验收**

- 插件调 `player.control next` 能切歌；连发 30 次/秒时被限频丢弃并有日志。
- 插件调 `platform.search('wy', '周杰伦')` 返回的结果与搜索页点网易云胶囊的结果一致（字段逐个比对）。
- 插件无法调 `platform.getAccount`（能力名不存在，报"未知能力"而不是返回 null）。

**坑**

- `platform.*` 的返回里有 `raw: unknown`（平台原始对象）。**跨 Worker 传之前必须裁掉 `raw`**，只给归一化字段 + `songmid`。带着 `raw` 走结构化克隆会偶发失败（平台对象里可能存在不可克隆值）。
- `getPic` 返回的是 URL 字符串，不是二进制。插件拿它自己决定怎么用。

### S3 · 可视化插件插槽（L2，3 天）

**目标**：插件拿到「频谱数组 + 一块画布」，自己画。**投入产出最高的一个插件位**：沙箱干净、表现力上限高、不碰布局、可能出圈。

**前置**：S0。

**改动点**

1. 新增 `plugin.visualizer.register` 能力：插件声明 `{ id, name, preferCanvas: true }`，宿主在播放页给它一块 `<canvas>`。
2. 宿主侧新增组件 `components/PluginVisualizer.tsx`：负责 canvas 尺寸（按 dpr）、rAF 循环、暂停时停循环、卸载时销毁。**插件不碰 rAF 生命周期**——这是这个项目最容易踩的坑（rAF 里读 `getBoundingClientRect` 会强制 reflow；`will-change` 撤销那一刻会整页重栅格化）。
3. 每帧只往插件发一个 `Float32Array`（或普通 number 数组，视 WebView 104 的 Transferable 支持而定），**不传 DOM、不传 React 元素**。
4. 播放页视觉区加一个切换入口（现有 `SpectrumLayer` / `DiscSpectrum` 旁边，数据结构一致，`spectrum(): Promise<number[]>`，40 段）。

**验收**

- 插件可视化能随音乐动，暂停后 rAF 停（用 `requestAnimationFrame` 计数验证：暂停 3 秒内不应有新帧）。
- 切走播放页后插件收到 `detach`，循环停；切回来重新 `attach`。
- 真机（安卓）上 60 帧不掉的底线：连续 10 秒采样，`over33` 不明显劣化（对照组：内置频谱）。
- 插件画布尺寸随窗口变化正确（dpr 变化也要跟）。

**坑**

- **禁止**在插件侧写 `will-change`。项目已有结论：撤销那一刻整页从合成层回落并重栅格化（实测 227ms），正好卡在动画收尾。
- 插件 canvas 必须显式 `width/height`（dpr 乘过），不要靠 CSS 拉伸，否则真机上是糊的。
- 播放页是**常驻挂载**的（关闭态 `opacity: 0.004` 保 tile）。插件循环必须跟「播放页是否可见」绑定，不能只跟"是否在播"绑定。

### S4 · 主题升格为"视觉语言"（L1，2 天）

**目标**：现在 `ThemeTokens` 30 个字段全是颜色 + 少量数值，只能"改色"。补上字体、封面滤镜、动效曲线，主题才是一个有吸引力的插件品类。

**前置**：无（与 S0–S3 无依赖，可并行）。

**改动点**

1. `packages/theme-engine/src/index.ts` 的 `ThemeTokens` **增量**加字段（不要改已有字段名，会破坏已导出的主题文件）：
   ```ts
   fontDisplay?: string      // 标题字体族
   fontBody?: string
   coverFilter?: string      // CSS filter，如 'contrast(1.08) saturate(1.1)'
   grain?: number            // 0–1，颗粒叠加强度
   durationPage?: number     // 页面转场
   curvePop?: string         // cubic-bezier
   ```
   全部可选，缺省走现有值 → **老主题包不需要迁移**。
2. `ThemeProvider` 已有 `root.style.setProperty` 循环（`ThemeProvider.tsx:114`），把新字段映射成 CSS 变量即可，不新增机制。
3. 主题包 = 一个 JSON 文件放进主题目录（复用现有导入导出与校验），不再只从设置页手动导入。

**验收**

- 老主题（不含新字段）加载后视觉与现在**逐像素一致**（截图对比）。
- 新字段生效：字体、封面滤镜、动效曲线各验一项。
- 主题文件校验能拒绝非法值（`coverFilter` 不是合法 CSS 时降级为 `none`，不整包失效）。

**坑**

- **`<html>` 上写自定义属性 = 整棵文档 recalc**（实测 1217 元素 / 26–36ms）。主题切换必须"值没变就不写"，不要每次 render 全量写一遍。
- WebView 104 **没有 `color-mix()`**（本项目已有大量 `color-mix` 在 `home.css`，但都是装饰性属性，失效不致命）。新字段不要引入 `color-mix` 或 `:has()`。
- 字体文件会进 `assets/www`，体积与授权都是问题。**v1 只允许引用系统字体族名**，不允许打包字体文件。

---

### S5 · 平台插件地基 + Subsonic 官方示例（L4，1.5–2 周）

**目标**：让"接一个新平台 = 放一个文件"。这是唯一能改变用户规模的插件面（NAS 用户）。

**前置**：S2（需要 `platform.*` 代理先跑通，正好复用同一套转发逻辑）。

**难度为什么是 L4**：`kw.ts` 815 行、`kg.ts` 703 行说明"接一个平台"的固有复杂度。**这是门槛的硬伤**——第三方作者要写几百行才接得动一个平台。所以**先由官方写 Subsonic 示例**（它的协议只有几个 GET + token，是最容易的第一个平台插件），用它验证地基，而不是指望社区。

**改动点**

1. `PlatformSource` 从字面量联合放开成 `string`（`types.ts:10`）。**这是唯一的前置破坏性改动**，影响所有带 `source` 字段的结构。类型上会松（编译期不再校验平台名）——用运行时的注册表校验补回来。
2. 平台元数据从代码与 CSS 移出：
   - `PLATFORM_NAMES`（`types.ts:12`）→ 运行时注册表
   - 平台配色现在写死在 CSS：`styles/search.css:250` `.sr-badge[data-src='wy']`、`styles/login.css:283` `.home-plat[data-src='wy'] .home-plat-dot` → 改成 manifest 里的色值 + inline `--src-color` 变量。**这是唯一必须动样式的地方，约 8 处。**
3. `platforms/index.ts` 的 `FACTORIES` → 运行时注册表 + 内置平台照旧注册（内置的走编译期，第三方的走插件装载）。
4. 新建命令 `plugins_platform_register`（或直接走 S0 的 RPC）——第三方平台在**主线程**加载（不进 Worker）：
   - 理由：平台层被 UI 高频调用，走 postMessage 有序列化成本；且返回里带 `raw`，跨线程不可靠。
   - 代价：主线程跑第三方代码。缓解：只给 `HttpClient`，**不给任何 DOM/全局**（用 `new Function` 包一层，参数只注入 `http`）。这是已知的折中，LX 脚本走 Worker 是更安全的方案，但平台层不适合。
5. 官方 Subsonic 插件（`plugins/subsonic/`）：`search / getPlaylistDetail / getPic / getLyric`，认证用 `u + t=md5(pwd+salt) + s=salt`。

**验收**

- 删掉 `kw.ts` 的 import（临时验证，验证完恢复），用一个外部 JS 注册同名平台，搜索/歌单/歌词/封面/起播全通。
- Subsonic 插件连一个真实 Navidrome 实例：搜索、取歌单、播放、封面四项通过。
- 第三方平台的圆点颜色/角标颜色来自 manifest，不来自 CSS。
- `platPrefs` 的 `hidden`/`order` 对第三方平台生效（键 `${source}:${id}` 天然兼容）。
- 第三方平台的歌在重启后能还原（`onlineId` = `online:平台:id` 字符串拼接，天然兼容）。

**坑**

- **不要**把 `raw` 交给第三方平台之外的地方；平台插件自己产出的 `raw` 也只能给宿主自己的后续请求用。
- 安卓侧 `Http.kt` 用 `HttpURLConnection`，**非标准 method 会抛 `ProtocolException`**（只允许 GET/POST/HEAD/OPTIONS/PUT/DELETE/TRACE）。Subsonic 全是 GET，没问题；但如果以后有平台插件要用 `PROPFIND`（WebDAV），必须先把安卓出网换 OkHttp。
- 平台插件的网络请求**必须**走宿主 `HttpClient`，不允许自己 `fetch`——否则 CORS 在 WebView 里必死，且无法审计。

### S6 · 歌词源管道（L3，3–5 天）

**目标**：把"歌词"从平台层剥成独立管道，允许多源 + 用户手动换源。

**前置**：S1（要用曲库查询找同名歌做匹配）。

**改动点**

1. 现在 `getLyric` 是 `PlatformApi` 的一个方法。新增 `LyricProvider` 概念：
   ```ts
   interface LyricProvider {
     id: string; name: string
     getLyric(q: { title, artist, album?, duration? }): Promise<{ lyric, tlyric? } | null>
   }
   ```
   内置 provider = 现有平台 `getLyric` 的适配器（**不要重写**，包一层）。
2. `lib/lyrics.ts` 的取词顺序改成「provider 列表按优先级逐个试」，全失败再报"没有歌词"。
3. 播放页歌词面板加"换源"入口（现有交互可复用 `ChipMenu`）。
4. 对轴：`lib/lyricAlign.ts` 已存在，不要让插件重写对轴，**对轴算法本身可作为 S6.b 的算法插件**（见附录 E）。

**验收**

- 有歌词的歌：默认路径与现在行为一致（不能因为加管道而变慢或变差）。
- 插件 lyric provider 注册后，在"换源"里出现，选中后能覆盖默认歌词。
- 多 provider 时，第一个失败会静默走第二个（不弹错）。
- 错配保护：插件返回的歌词如果与当前歌明显不符（标题/歌手对不上），不静默采用——用 `titleMatch.ts` 判一次。

**坑**

- 歌词是**大字符串**（几 KB），走 RPC 要压缩或分块，否则桌面端还好、安卓上滚歌词会掉帧。
- 桌面歌词（`DesktopLyrics`）与浮窗歌词共用一份 `LyricsDoc`，插件返回的歌词必须走同一条解析路径（`lyrics.ts`），不要另造结构。

### S7 · 声明式 UI slot（L5，2 周+，**建议本版不做**）

**目标**：允许插件在自己的位置放内容，但**不是**任意 React——宿主渲染，插件只给数据。

**为什么排最后、且建议不做**：这是纯新增工程量（渲染器 + 组件白名单 + 布局约束 + 主题兼容 + 布局回归测试 + 两端一致），而且播放页是常驻挂载 + rAF 预算的敏感区。S3 已经能满足"视觉扩展"的需求。

**如果一定要做，限制到这三处**：播放页底部一行、设置页一个卡片、侧栏一项。形状：

```jsonc
{ "slots": [{ "at": "player.under-cover", "type": "row", "items": [
  { "type": "text", "bind": "nowPlaying.album" },
  { "type": "button", "label": "相似歌曲", "cmd": "similar" }]}]}
```

**明确不做**：能替换整页、能改播放页布局、能注入任意 CSS。

**拿不到的能力（别再尝试）**

- 音频样本（DSP/EQ 插件）：`audioFx` 的处理在 **Rust 音频线程**（解码后、取样前），安卓是 media3 的 `AudioProcessor`。JS 碰不到。

## 附录 C · 接口草案（v1 冻结范围）

**形态**：RPC + 事件，**不给插件一个 JS 对象**。因为插件必须在 Worker 里跑（两端一致、崩溃隔离、LX 音源已验证）。对象跨不了线程。

```js
// 插件侧
const r = await host.call('library.query', { text: '民谣', limit: 50 })
host.on('track', t => scrobble(t))
```

底层就是 `postMessage({ id, method, params })` ↔ `{ id, result }`，事件是 `{ event, payload }`。以后从 Worker 换到 iframe / 独立进程，**插件代码一行不用改**。

**v1 只冻结这三类**（确定不会再变）：

1. 能力名：`log` / `toast` / `storage` / `net.request` / `library.query` / `player.control` / `player.enqueue` / `platform.*`（免登录 5 个）
2. 事件名：`track` / `state` / `queue` / `progress` / `lyric` / `ready` / `dispose` / `vis.frame`
3. `library.query` 的查询参数（见 S1）与 `player.control` 的 `op` 枚举

**其余全部标 `preview`，不承诺兼容**：slot 位置、插件 UI、可视化注册细节、主题扩展字段。理由：本项目还在快速演进，冻结太早会把自己拖死。

**版本**：manifest `engine: "^1.0"` + 宿主 semver 检查；不匹配拒绝装载并说明原因。

**权限文案**（安装页要用人话，不是能力名）：

> 这个插件会：访问 `ws.audioscrobbler.com`、读取你的曲库（只读）、在换歌时收到通知。

## 附录 D · 给实现者的约束

1. **默认不编译、不出包**：改完用热注入 + 截图验证；用户说编译才 `tauri build` / `gradlew assemble`。打包窗口内不改代码。
2. **不动主题引擎 / 启动页 / 本地扫描核心**。S4 只允许在 `ThemeTokens` 上**增量加可选字段**。
3. **验证只信实测**：CDP 量 DOM / `app.log` / `adb screencap`。不要写"应该没问题"的旁白。
4. **出网必须走 Rust `net_request`**（例外仅有 `lib/cloudFetch.ts`，那是腾讯云网关的 Origin 白名单问题）。
5. **提示用 `lib/toast.ts`，确认用 `lib/confirm.ts`**，不要新造。
6. **安卓 = 换壳**：前端进 `assets/www`，差异只落 `data-shell` CSS 与 `bridge.isNative`。
7. **`<html>` 上写属性/自定义属性 = 整棵文档 recalc**。任何 html 级写入都必须"值没变就不写"。
8. **WebView 104 没有 `color-mix()` / `:has()`**，失效是 IACVT（不回落）。新代码别引入。
9. **每个阶段结束必须跑**：`tsc --noEmit` + `vite build`。安卓产物同步只在用户发话时做。
10. **每阶段只做这一阶段的事**。想顺手做 S(n+1) 的接口，先停下来——不确定的东西会污染 v1 契约。

## 附录 E · 已证伪 / 已排除的路线（别再走一遍）

| 路线 | 为什么排除 |
|---|---|
| 通用插件运行时（iframe + 任意 React + 沙箱） | 维护成本远超收益；性能预算（120Hz/rAF/整文档 recalc）会被打穿；安卓是换壳，第二 WebView 的代价不成比例 |
| 插件跑 React | 版本绑定 + 样式污染；改一个 `:root` 变量就是整文档重算 |
| 插件直接调 `@tauri-apps/api` | 安卓端必崩 |
| 插件自带原生代码 | 构建链路/ABI/签名全要重做，两端立刻分裂 |
| DSP / EQ 插件 | 处理在 Rust 音频线程与 media3 `AudioProcessor`，JS 碰不到 |
| 先建市场再做插件 | 市场死于"没有插件"。先自己写 3–5 个示例，验证有人照着写，再建市场 |
| 代替方案（若插件生态不动） | 做"**配方分享**"：主题 + 布局偏好 + 快捷键 + 音源清单打成 `.json`。零代码门槛，一天成本，能直接测出用户想不想扩展 |

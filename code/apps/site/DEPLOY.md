# 官网部署 + 使用统计上线

两件独立的事，可以分开做。顺序建议：**先挂安装包 → 再传页面 → 最后接统计**
（页面上的下载按钮指向 Releases，链接先通，页面才不至于一堆灰按钮）。

---

## 零、先跑一次构建

```bash
cd code/apps/site
node build-site.mjs
```

产物两份，职责不同：

| 目录 | 内容 | 传给谁 |
|---|---|---|
| `dist/site/` | `index.html` + `assets/` + `downloads.json`，约 58 KB | 静态托管 |
| `dist/release/` | 五个安装包，约 28 MB | **Gitee Releases** |

脚本会扫 `dist/` 与它的一级子目录（`dist/2026-11-22/` 这种按日期归档的也能扫到），
按文件名里的版本号 + 修改时间挑最新的一份，并把 `downloads.json` 的版本号、体积、下载地址全部对齐。

跑完会打印每个包的最终下载地址，后面几节要用。

## 一、安装包上架（Gitee Releases）

**下载源是 Gitee，不是 GitHub。** 国内 Gitee 能跑满带宽，GitHub 的 releases 经常只有几百 KB/s
甚至直连失败；而 GitHub 只留作源码镜像。

### 为什么不用 Gitee 的 raw 地址

raw 匿名下载有大小上限，实测过：

| 文件 | 大小 | `raw/master/...` 结果 |
|---|---|---|
| `shuyin-android-0.6.111.apk` | 4.0 MB | ✅ 200 |
| `shuyin-ios-0.5.25.ipa` | 4.6 MB | ✅ 200 |
| `shuyin-macos-0.5.25.dmg` | 10.3 MB | ❌ 403 |

Releases 附件没有这个问题，而且路径和 GitHub 同构，`downloads.json` 里的 `base` 换一行就行：

```
https://gitee.com/ghpgitee/shuyin-update/releases/download
```

### 怎么发

```bash
python code/apps/site/tools/publish-gitee.py --dry-run   # 先看要传什么
python code/apps/site/tools/publish-gitee.py             # 真传
```

脚本会按文件名里的版本号自动分组，一个版本一个 Release 挂多个附件：

| tag | 附件 |
|---|---|
| `v0.6.111` | `shuyin-android-0.6.111.apk`、`shuyin-car-0.6.111.apk` |
| `v0.5.25` | `shuyin-windows-0.5.25.exe`、`shuyin-ios-0.5.25.ipa`、`shuyin-macos-0.5.25.dmg` |

已存在的附件会跳过，所以**失败了直接重跑同一句**，只补缺的（Gitee 偶发连接重置，重传即可）。

token 从 `git credential fill` 取（需要有 `ghpgitee/shuyin-update` 的写权限），
也可以 `export GITEE_TOKEN=...` 指定。

> 仓库必须是 **public**。私有仓库的附件匿名下载返回 403，页面上所有按钮都会废掉。

当前这五个包已经发好了，改版时只有出新包才需要重跑。

## 二、传页面

### 方案 A：腾讯云 CloudBase 静态托管（推荐，国内直连快）

你已经有环境 `basic-goldfish-d8gw3lzl9219b11d4`（云同步也在上面）。

1. 打开 `https://tcb.cloud.tencent.com/dev?envId=basic-goldfish-d8gw3lzl9219b11d4`
2. 左侧找 **静态网站托管**；没开通过就先点「开通」（免费体验版够用）
3. 进「文件管理」，把 `dist/site/` 里的东西**按原结构**传上去：

   ```
   /index.html
   /downloads.json
   /assets/icon.png
   /assets/icon-32.png
   ```

   注意 `assets/` 要一起传，且保持在根目录下的 `assets/` 里——`index.html` 里写的是相对路径。

4. 传完在**同一个页面**找访问域名 —— 以控制台显示的为准，**不要自己拼**。

   实测踩过的坑：`https://<环境ID>.tcloudbaseapp.com` 这种拼法在新环境上直接回
   `INVALID_HOST`（`server: tcbgw`，网关收到了请求但不认识这个 host，说明这个域名
   根本没分配给任何环境）。**静态托管没开通就不会分配域名**，开通后控制台才给出一条真地址，
   形如：

   ```
   https://<一串数字>.ap-shanghai.app.tcloudbase.com
   ```

   也可以命令行查（需要先 `tcb login`）：

   ```bash
   tcb hosting detail -e basic-goldfish-d8gw3lzl9219b11d4
   # 托管状态：未开通 / 初始化中 / 正常
   # 访问域名：<真实地址>
   ```

   > 状态是「初始化中」时上传会被拒，等几分钟再传。

### 默认域名的两个硬限制（2026 官方口径）

拿到真域名也别高兴太早，默认域名（`*.tcloudbaseapp.com`、`*.app.tcloudbase.com` 等）有两条限制：

1. **浏览器直接访问会先弹「访问提醒」中间页**：官方对默认域名做了限制，
   `Sec-Fetch-Mode: navigate` 的请求会先显示一页「当前环境仅供开发测试、内容未经过合规审核」，
   用户必须点「确认访问」才进得去。（点过一次后，同一域名在 cookie 有效期内不再拦。）
2. **明确禁止用于生产**：官方原文「严格禁止在生产环境或大规模分发中使用」，平台实时监控
   默认域名访问量，异常波动会直接风控拦截。

**想要一个干净的官网地址，合规路径只有绑自定义域名**，而免费环境走不通这条路：

| 条件 | 要求 | 你的情况 |
|---|---|---|
| 套餐版本 | 个人版及以上 | ❌ 免费体验版 |
| 环境剩余有效期 | > 6 个月 | 单次 6 个月，临界 |
| 云托管固定 IP | 已开启 | ❌ 未开 |

所以现阶段的现实选择：**默认域名 + 中间页**（自己看、小范围发能用），
或者走下面的方案 B（Cloudflare Pages，`*.pages.dev` 实测 1.07s 可达、无中间页、免备案）。

**额度提醒**：这个免费环境和云同步共用 3000 资源点/月。页面 58 KB，正常推广不会撞线。
**别把安装包传进来**——28 MB × 几百次 = 上百 GB 的 CDN 流量，额度一耗尽整个环境停服，
连云同步一起停。安装包放 Gitee 就是为了把这块流量挪走。

以后改版只需覆盖 `index.html`；只发新版时**只覆盖 `downloads.json`**（1 KB），页面不用重传。

### 方案 B：Cloudflare Pages（带宽不计费，但国内时快时慢）

1. `dash.cloudflare.com` → Workers & Pages → Create → Pages → **Upload assets**
2. 把 `dist/site/` 整个目录拖进去
3. 拿到 `xxx.pages.dev`，长期有效，不用域名也不用备案

想同时要国内速度和无限带宽，可以两边都传：主域名指 Cloudflare，国内用户走 CloudBase。

### 传完后自检四条

- 首屏左上角那行小字显示的是 `v0.6.111 · 熄屏与锁屏播放`
- 五个下载卡片的按钮是亮的、能点、真的开始下载，地址落在 `gitee.com`
- 平台区六张卡：Windows / Android 手机 / 车机 / 平板 / iPhone / macOS
- **手机打开看一遍**：首屏要能看到两个下载按钮，导航右侧有个汉堡按钮，点开是四个锚点

## 三、使用统计

客户端已经写好了（`code/apps/desktop/src/lib/stats.ts`），**只差一个服务端地址**。
现在的 `STAT_ENDPOINT` 是空串，空串等于整个模块 no-op：不连网、不写盘、不影响任何功能。

### 3.1 收的是什么、能回答什么

| 事件 | 触发时机 | 服务端落到哪 | 能回答 |
|---|---|---|---|
| `first` | 每台设备**第一次**启动（本地记标记，只发一次） | `stat/machines/<装机号>.json` | **总共有多少台设备用过疏音** |
| `ping` | 每天首次启动（24 小时间隔） | `stat/days/<北京时间当天>/<装机号>.json` | **今天有多少人在用**（日活） |
| `dl` | 应用内更新装完包 | 同 `ping` | 更新安装量 |

关键点：**「多少人用过」不看下载量，看有没有真跑起来**。从官网、Gitee、别人传的 APK
哪来的都算一次；反过来，下了没装、装了没开的不算——这正好避开「下载量虚高」的问题。

口径说明：装机号是首次运行随机生成的 UUID，**清数据 / 重装会变成一台新设备**，
所以这个数字是「设备数」而不是「人数」，会略微偏高。

### 3.2 建云函数

代码在 `code/apps/site/cloud/stat/`（`index.js` + `package.json`）。

1. 控制台 → **云函数** → 新建云函数
2. 函数名填 `stat`（后面 HTTP 路径要用它），运行环境选 **Node.js 18**
3. 创建方式选「上传代码包」而不是在线粘贴——`package.json` 里有两个依赖
   （`@cloudbase/node-sdk`、`@cloudbase/manager-node`），需要一个能装依赖的入口
4. 超时时间 10 秒，内存 128 MB（报表要列目录，5 秒不够）

> 如果只能用在线编辑：`@cloudbase/node-sdk` 是平台内置的，粘 `index.js` 就能写入；
> 但**报表会退化**——GET 时返回一条提示，让你去控制台数文件。写入不受影响。

### 3.3 开一个 HTTP 入口

1. 控制台 → **HTTP 访问服务**（有的版本叫「HTTP 触发器」/「云接入」）
2. 新建一条：路径填 `/stat`，指向 `stat` 函数，方法允许 `POST` **和 `GET`**
3. 保存后会拿到一个地址，形如：

   ```
   https://basic-goldfish-d8gw3lzl9219b11d4-xxxxxxxx.service.tcloudbase.com/stat
   ```

   具体域名以控制台给的为准，**复制完整地址**。

### 3.4 先用 curl 打通，再改代码

在电脑上跑一次（把地址换成上一步拿到的）：

```bash
# 模拟一台设备首次启动
curl -i -X POST "https://<你的地址>" \
  -H "Content-Type: application/json" \
  -d '{"t":"first","app":"desk","ver":"0.5.25","mid":"test-machine-0001","at":0}'

# 模拟当天活跃
curl -i -X POST "https://<你的地址>" \
  -H "Content-Type: application/json" \
  -d '{"t":"ping","app":"desk","ver":"0.5.25","mid":"test-machine-0001","at":0}'
```

期望都返回 `200` 且 body 是 `{"code":0,"stored":true}`。

然后回控制台看 **云存储**，应该出现两条路径：

```
stat/machines/test-machine-0001.json
stat/days/2026-11-22/test-machine-0001.json
```

> 返回 `stored:false` 说明函数跑通了但写文件失败——去云函数日志里搜 `STAT_WRITE_FAIL`，
> 一般是没给云函数开云存储写入权限，或者环境里没有默认存储桶。

### 3.5 看数字

**方式一：浏览器直接打开那个地址**（GET）

```
https://<你的地址>
```

返回：

```json
{ "ok": true, "total": 128, "today": 12, "day": "2026-11-22" }
```

`total` = 用过疏音的设备总数，`today` = 今天活跃。

这条走管理端 SDK 列目录，几千个文件时会慢一两秒，属于正常。不想每次都等，就加个
浏览器书签，一天看一次。

**方式二：控制台数文件**（报表返回 `ok:false` 时的兜底）

| 想知道 | 去哪看 |
|---|---|
| 多少人用过 | 云存储 → `stat/machines/` → 文件总数 |
| 今天多少人在用 | 云存储 → `stat/days/<今天>/` → 文件总数 |
| 上周某天多少 | 换 `stat/days/` 下的日期目录 |
| 手机 / 车机 / 桌面各多少 | 点开任意 json 看 `app` 字段 |
| 各版本分布 | 看 `ver` 字段 |

想批量算，把 `stat/` 整个下载下来跑：

```bash
find stat -name '*.json' -path '*machines*' | wc -l          # 累计设备数
find stat/days/2026-11-22 -name '*.json' | wc -l             # 某天日活
```

### 3.6 额度：这套统计到底吃多少

先从官方定价换算（资源点计费，1000 点 ≈ ¥1，免费环境 3000 点/月）：

| 计费项 | 单价 |
|---|---|
| 云函数调用 | 13.3 点 / 万次 |
| 云存储写请求 | **10 点 / 万次** |
| 云存储容量 | 3.94 点 / GB / 天 |
| 文档型数据库调用 | 200 点 / 万次 |
| 文档型数据库容量 | 40 点 / GB / 天 |
| CDN 流量 | 210 点 / GB |

按 **1000 台设备、日活 300** 估算（每月）：

| 项目 | 用量 | 消耗 |
|---|---|---|
| 云函数调用 | 1 万次（300×30 + 1000 首登） | 13 点 |
| 云存储写 | 1 万次 | 10 点 |
| 存储容量 | 约 1.2 MB（每个文件 120 字节） | 0.2 点 |
| **合计** | | **约 23 点 / 月** |

**占免费额度不到 1%。** 这就是为什么把统计放云存储、不放数据库：

- 同样是 1 万次写入，文档库要 200 点，云存储 10 点，**差 20 倍**
- 容量单价差 10 倍（40 vs 3.94）
- 而且完全不占数据库额度

所以答案是：**统计本身几乎不耗额度**（每月约 23 点），改到云存储也确实比放数据库省二十倍。

但有一件**反直觉的事**，2026-11 控制台实测明细推翻了本文早前的判断：

| 服务 | 实测消耗（22 天） | 明细 |
|---|---|---|
| **PostgreSQL** | **1139.45 点（99.7%）** | CU 3.33 核时；存储 231 MB·时（实时 0MB） |
| 环境调用 | 2.32 点 | 云开发 API 232 次 |
| 日志 | 0.55 点 | 存储 1.99 MB / 流量 1.49 MB |
| 云存储 | **0.01 点** | 调用 5 次、容量 0、CDN 0 |
| 云函数 / 云托管 / AI | 0 | — |

那 1139 点**既不是同步、也不是统计**，是新版环境自带的 PG 实例在**待机**：
云存储的元数据（`storage.objects` / `storage.buckets`）就是 PG 里的普通表，Storage API
「事务内协调元数据与对象」，所以每次存储操作都在事务里碰一下库；而 PG 共享实例按
**5 分钟窗口**计费——窗口内只要有任意一次访问，就算 `0.5 核 × 5/60 = 0.04167 CU`。
**0 个用户在线也在烧**，折算每月约 1500 点 ≈ 免费额度的一半，这就是「数据库占了一半」的来源。

⚠️ **对统计的直接影响（上线前必看）**：`ping` 每上报一次就写一次存储 = 唤醒一次 PG 的计费窗口。
统计真跑起来、每天上千次上报散落在全天时，PG 会全天不睡：
288 窗口/天 × 0.04167 = 12 CU/天 ≈ 360 CU/月 ≈ **12 万点/月**（对现在 4.5 CU/月，差 80 倍）。
所以**统计上线前必须先把上报频率压住**——每台设备每天最多一次、客户端攒批，
否则额度会死于 PG 的唤醒次数，而不是死于统计本身的调用量。

另外，PG 在新版 CloudBase 里**删不掉**（控制台新建环境统一为 PG 模式，传统模式只在存量环境）。
真要彻底甩掉这 1500 点，只能把同步 + 统计整体迁出 CloudBase，属改造项，与官网部署无关。

**别开「超限按量付费」**：免费环境不支持，付费环境开启后会按 0.21 元/GB 扣 CDN 流量，
推广期一篇文章就能烧掉几十块。

### 3.7 把地址写进客户端，重新打包

改 `code/apps/desktop/src/lib/stats.ts` 里的常量：

```ts
export const STAT_ENDPOINT = 'https://<你的地址>'
```

然后推一次 CI（四平台一起出包）。**这一条必须重打包才生效**，因为它是编译进前端的常量。

新包装上后，行为是：

- 首次启动：发一条 `first`，成功才落本地标记（失败下次启动再试，不会丢设备）
- 每 24 小时：发一条 `ping`
- 应用内更新装完包：发一条 `dl`
- 全部静默：断网、超时、服务端 500 都不弹提示，也不写时间戳

上报内容只有：随机装机号、版本号、形态（phone / car / desk）、时间。
没有账号、没有设备序列号 / MAC、没有位置、没有任何听歌内容。

**官网 FAQ 里没提这件事**——页面上「我的数据会被上传吗」只讲曲库/播放记录/收藏都在本机

## 常见问题

**页面打开显示「下载地址尚未配置」**
`downloads.json` 没取到。`file://` 直接双击打开会被 CORS 拦掉，必须走 HTTP。
本地调试：仓库根目录跑 `node tmp/site-serve.mjs`，访问 `http://127.0.0.1:5301`。

**按钮点了 404**
Release 里的附件名和 `downloads.json` 的 `file` 字段对不上。名字必须完全一致，
包括版本号。改完只需重传 `downloads.json`。

**dmg 用 raw 地址下不下来（403）**
Gitee raw 对超过约 5 MB 的匿名下载会拒。走 Releases，别用 raw。

**iPhone 下载了装不上**
IPA 是未签名的，必须自己用 Sideloadly / 爱思助手配合 Apple ID 签一次名。这是预期行为，
页面上「未签名」标签和 FAQ 都写了。

**统计一直没数据**
按这个顺序查：`STAT_ENDPOINT` 是否还是空串 → 是否重新打包过 → HTTP 路径是否 `/stat` →
云函数日志里有没有 `STAT_OK`。日志里有 `STAT_OK` 但存储里没文件，就是权限问题。

**报表 GET 返回 `ok:false`**
说明 `@cloudbase/manager-node` 没装上（或环境 ID 取不到）。写入不受影响，
按 3.5 的「方式二」去控制台数文件；想修就把依赖装上重新部署函数。
